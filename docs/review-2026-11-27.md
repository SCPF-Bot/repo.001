# MLBB Plus — Repository Review and Refactor (2026-11-27)

This is the full review requested for the repository, followed by the refactor it drove. It covers the Gradle root, the `:app` module, the CI workflows, the scripts, the JSON assets, the documentation and the Kotlin sources. Each finding has a status:

- **FIXED** — changed in this pass and verified (see §2 for how).
- **OPEN** — confirmed, not changed here. Each has a recommendation.
- **DECISION** — needs a product or maintainer call before it can be changed.

The repository is not committed. All changes are in the working tree of `repo.001`, so they can be reviewed with `git diff`.

## 3. Findings fixed in this pass

### 3.1 Build and Gradle

1. **FIXED (High) — sherpa-onnx AAR URL 404.** `app/build.gradle.kts` used `github.com/k2fsa/…`, which returns 404. Now `github.com/k2-fsa/…`. The pinned SHA-256 matches the published AAR.
2. **FIXED (High) — debug build needs a file that is never created.** `debugConfig` pointed to `${rootDir}/debug.keystore`, which is gitignored, so `validateSigningDebug` failed on every clean checkout. Debug builds now use AGP's default debug keystore.
3. **FIXED (High, security) — release artifacts signed with a public password.** `release.yml` generated a keystore with the password `mlbb-test-store` when secrets were absent, so the "release" APK/AAB was signed with a key anyone could reproduce. Release signing is now opt-in: with `KEYSTORE_PATH` / `STORE_PASSWORD` / `KEY_PASSWORD` / `KEY_ALIAS` set, the release is signed; without them, it is built unsigned and CI prints a notice.
4. **FIXED (Medium) — downloads could leave corrupt files.** `downloadSherpaAar` and `bundleTtsModels` now share `VoiceGuideFetch.downloadVerified`: the file is written to `.part`, its SHA-256 is checked, and only then is it moved into place. A pinned file that no longer matches is re-downloaded.
5. **FIXED (Medium) — Gradle wrapper missing.** The repository had no `gradlew`, `gradlew.bat` or wrapper JAR, so the readme's `./gradlew` commands and CI's `gradle` invocation depended on a host install. The wrapper is generated and pinned to **Gradle 9.3.1**. `release.yml` uses `./gradlew`.
6. **FIXED (Low) — project name.** `settings.gradle.kts` had `rootProject.name = "MLBB Assistant 2.0"`. Now `MLBB Plus`. Removed the dead `googleServices.missing.passthrough` property from `gradle.properties`.
7. **FIXED (Medium) — configuration cache.** The new download helpers initially broke the configuration cache. They are now members of a nested `object VoiceGuideFetch`, and the task actions capture only local values.

### 3.2 CI workflows

8. **FIXED (High) — `extract.yml` could wipe the repository.** It ran on every push that touched a root-level `*.zip` or `*.tar.gz`. Its first step deletes every top-level file except `.github`, `.git` and archives, then commits and pushes to `main`. A stray upload would delete the whole source tree. The workflow is now `workflow_dispatch` only. It refuses to run without an archive present and tests each archive (`unzip -t`, `tar -t`) before deleting anything. Uses `actions/checkout@v7`.
9. **FIXED (High) — `update-tts-models.yml` claimed a trigger chain that did not exist.** Its header said the release workflow is chained by `workflow_run`, but `release.yml` has no such trigger, and a commit pushed with `GITHUB_TOKEN` does not fire `push` workflows. Releases therefore never built after a manifest update. The workflow now runs `gh workflow run release.yml --ref main` after a changed manifest is pushed (the one event `GITHUB_TOKEN` may trigger).
10. **FIXED (Medium) — failed update could pass.** The update step piped the script into `tee` without `pipefail`, so an exit-1 from the updater was hidden. `set -o pipefail` is now on. The cache also gained `restore-keys`.
11. **FIXED (Medium) — release workflow had no validation.** `release.yml` now runs `scripts/validate_assets.py` before the build (the refactoring report claimed this and it was missing). It keeps `:app:testDebugUnitTest` and `:app:lintDebug` in the same step as the debug build, now through `./gradlew`.
12. **FIXED (Low) — keystore handling.** Release keystores are written to `$RUNNER_TEMP`, outside the checkout, so no cleanup step is needed.

### 3.3 Tests

13. **FIXED (High, for CI) — Robolectric on JDK 17.** `AppStateAndNavigationTest` ran on `@Config(sdk = [36])`, which Robolectric 4.18 only supports on Java 21+. CI and the build use JDK 17, so the test class always failed. It now runs on SDK 35. The app's `targetSdk` is unchanged. See DEC-3 if JDK 21 is preferred instead.

### 3.4 Kotlin: correctness and concurrency

14. **FIXED (High) — native use-after-free in the voice engine.** `SherpaOnnxVoiceEngine.releaseInternal()` freed the native `OfflineTts` while `speak()` could still be generating on an IO thread. Generation and the native free now share a `genLock`; the handles and `rate` are `@Volatile`; `load()` releases the engine when the track cannot be built, so a half-initialised engine is never published.
15. **FIXED (High) — a phone call could cancel a voice-pack download.** `VoiceGuideManager.stop()` cancelled the model installer. `stop()` is reached from audio-focus loss, TalkBack, the enable/disable toggle, deleting a model and notification stop. A 20–100 MB download could be discarded silently. Only `cancelInstall()` cancels now.
16. **FIXED (Medium) — cancellation reported as failure.** `VoiceModelInstaller.install` caught `Exception`, which includes `CancellationException`. A cancel was reported as a retryable error, and partial files could remain. Cancellation is now rethrown after the work directory is removed. The storage check also keeps a safety margin.
17. **FIXED (Medium) — `SystemTtsVoiceEngine` races.** `invokeOnCancellation` was registered after `tts.speak`, so a cancel that arrived first was missed. It is registered first now.
18. **FIXED (Medium) — JSON `null` crashed the loader.** The loaders called `has(key)` then `getJSONArray(key)`. `has` is true for a JSON `null`, and `getJSONArray` then throws. All array and object reads now use `optJSONArray` / `optJSONObject`, and the list helpers accept a null receiver. The shipped data does not trigger this, but a future export could.
19. **FIXED (Low) — static leak suppressed deliberately.** `JetOverlay` is a singleton holding a `View` and `WindowManager`. The view comes from the application context and is cleared in `hide()`, so nothing outlives the overlay. The lint `StaticFieldLeak` is suppressed on the object with that justification.
20. **FIXED (Low) — silent overlay failures.** `JetOverlay.show()` returned silently when the overlay permission was missing, and `addView`/`removeView` failures were swallowed. Each now logs under the `JetOverlay` tag, so "the guide never appeared" is diagnosable. Behaviour is otherwise unchanged.
21. **FIXED (Low) — accessibility.** The overlay's custom `FrameLayout` handled touches without reporting clicks. A tap that is not a drag now calls `performClick()`.
22. **FIXED (Low) — obsolete SDK checks.** minSdk is 29, so the checks for API 23, 24 and 26 were always true. Removed. The API 31 and 34 checks are real and stay.
23. **FIXED (Low) — deprecated `SharedPreferences` idiom.** Eleven `edit().put…().apply()` chains are now KTX `edit { }`.
24. **FIXED (Low) — dead code.**
    - `DeepLinks` in `AppRoute.kt`: defined, never referenced, no manifest intent filter. Removed.
    - `FIRST_TAP_ONLY_WAKES = false` and its `pointerInput` branch in `OverlayWidgets.kt`: unreachable. Removed, along with the `awakeNow` state only that branch used.
    - Nine unused colours (including a `github_*` palette from another project), 12 unused dimensions, 4 unused strings. Removed. `colors.xml` is deleted.
25. **FIXED (Low) — magic number.** The overlay game clock limit `18 * 60` appeared four times. It is now `GAME_CLOCK_MAX_SECONDS`.
26. **FIXED (Low) — duplicated image loaders.** `HeroImage` and `ItemImage` repeated the same load-or-fallback logic. They now share a private `AssetPortrait`. Call sites are unchanged.
27. **FIXED (Low) — stale identifiers.** `R.string.roam_guide_running` (the notification title for the whole app) is now `app_running_title`. Its unused companion `roam_guide_stop_hint` is removed.
28. **FIXED (Low) — stale version tags and changelogs in code.** `Models.kt`, `OverlayWidgets.kt`, `JetOverlay.kt` and `WidgetOverlayService.kt` contained "FIX [n]" and "V8/V9/V13" history comments and a "FIXES" changelog header. They are replaced by descriptive comments.
29. **FIXED (Low) — hard-coded version.** Settings showed `MLBB Plus v1.0` as a literal. It now reads `BuildConfig.VERSION_NAME`.

### 3.5 Resources and manifest

30. **FIXED (Medium) — adaptive icon had no themed layer.** Android 13+ themed icons need a monochrome layer. `ic_launcher_monochrome.xml` is derived from the foreground artwork: each shape keeps its own alpha, and colours become black.
31. **FIXED (Low) — backup policy was unused and undocumented.** `allowBackup="false"` disables backup, so the two sample rule files were dead templates. Both now have explicit contents. `data_extraction_rules.xml` excludes all data, which is intentional: the 145 MB voice packs are re-extracted from the APK, and restoring stale model state on a new device is not wanted. The manifest references both files.
32. **FIXED (Low) — manifest comment.** It now states the backup decision with its reason.

### 3.6 Documentation

33. **FIXED (High for trust) — the knowledge base described UI that does not exist.** Checked against the code:
    - "Hero Explorer's Sort by → Meta": there is no Meta option. The options are *Recommended*, *Win rate* and *Name*. *Recommended* sorts by tier, then win rate, which is what the text now says.
    - "Settings → Floating guide": there is no such entry. The Settings screen has an overlay-permission card with "Open Android settings" / "Manage Android permission". The text now describes that.
    - "Enemy spells": the toggle is labelled "Announce enemy battle spells". Corrected.
    - Verified as correct and left unchanged: "PERMISSION ON" (Home), "Start the guide when the app opens" (Settings), speeds 0.85× / 1.0× / 1.25× (`VoiceGuideSettings`), four voices (Kokoro female/male speakers in one 103 MB pack; Piper female and male, ~21 MB each), "Holds the sentence mid-way on the neural voices, restarts it on the system voice" (`VoiceGuideManager` comments and `phaseAfterResume`).
34. **FIXED (Medium) — stale versions.** `overview.md` and `structure.md` named AGP 9.2.1, Gradle 9.6.1, Kotlin 2.3.21, Compose BOM 2026.06.00, Core KTX 1.16.0, Coil 3.0.4, SavedState 1.2.1 and commons-compress 1.25.0. Updated in `overview.md`, `structure.md`, `tts_implementation.md` and `ux-redesign.md`.

## 4. Open findings

### OPEN-1 (High) — release build runs out of memory under R8

`:app:minifyReleaseWithR8` fails with `OutOfMemoryError: Java heap space` on this 2 GB sandbox at a 1.5 GB daemon heap. The likely cause is size: `material-icons-extended` contributes most of `classes.dex` (43 MB; a string scan finds tens of thousands of Material icon entries). The source references about 28 distinct icons directly (`Icons.Filled.*` and `Icons.AutoMirrored.Filled.*`), plus any reached through `AppIcons`. This is inferred from size and has not been confirmed by a heap-size experiment.

- **Recommendation:** replace `material.icons.extended` with `material-icons-core` plus the handful of icons the app actually uses. This shrinks the APK, reduces R8's work, and removes the memory risk. It is a visual change, so it needs a device check of every icon.
- **Also check:** whether CI's R8 step has enough heap. It inherits `-Xmx4g` from `gradle.properties` only if R8 runs in the daemon. Confirm with a green `assembleRelease` run on GitHub.
- **Not verified:** the R8 keep rules for sherpa-onnx JNI and for the Kotlin serialization classes. A release build that passes R8 still needs a smoke test of the voice engine on a device.

### OPEN-2 (High, product) — voice engine has no device test

The sherpa-onnx engine, the model installer and the overlay gestures need an on-device checklist (`docs/tts_implementation.md` §9 and `docs/overview.md`). Nothing in this pass touched that checklist. The native-free fix in §3.4 is verified by reading and by the build, not by running speech.

### OPEN-3 (High, maintainability) — three parsers for `<role>_guide.json`

The same guide file is parsed in three places: `OverlayWidgets.parseStep`/`parsePlan`/`loadGuide`, `Guides.kt` `GuideLoader`, and `Models.kt` `GameData.load`. They can drift, and the overlay and the Guides screen can show different steps for the same role. The duplication also means the null-safety fix in §3.4 had to be made in more than one place.

- **Recommendation:** a single parser in `Guides.kt`, used by the overlay and the screens.

### OPEN-4 (Medium) — `OverlayWidgets.kt` is 1,473 lines

It holds the overlay UI, the guide parser, the role-type menu logic (which duplicates `RoleTypes`), objective timer constants (which duplicate `ObjectiveTimers`), spell and abbreviation tables, and a log tag. Its header says it may not be split. That rule is a maintainer decision and should be revisited.

- **Recommendation:** move the tables and parser out; keep the composables together.

### OPEN-5 (Medium) — main-thread JSON parsing at startup

`GameData.load(this)` runs synchronously in `MainActivity.onCreate` and in `WidgetOverlayService.onCreate`. It parses `heroes.json` (about 730 KB) and `items.json` on the main thread. On a slow device this delays the first frame. Preferences are also read twice on startup.

- **Recommendation:** load on a background dispatcher behind a loading state; keep the in-memory maps as they are.

### OPEN-6 (Low) — dependency and toolchain upgrades

- AGP 9.5.3 and Gradle 9.9.2 are available (lint). Not upgraded: each upgrade needs its own build and device check.
- sherpa-onnx is pinned to 1.13.8. The docs record that 2.0.x drops the espeak-ng frontend that the Piper voices need; keep the pin until that is resolved.

### OPEN-7 (Low) — silent failures in parsing

- `Guides.kt`: `runCatching { … }.getOrNull()` drops a whole role with no log.
- `Models.kt`: `loadPatchNotes` falls back to an empty `PatchNotesFile()` with no log.
- `WidgetOverlayService`: its companion object holds process-wide `mutableStateOf`. `onDestroy` releases the voice engine (Kokoro holds ~200 MB) on the main thread.

- **Recommendation:** log these, and move the release off the main thread.

### OPEN-8 (Low) — text normaliser abbreviations (unverified)

`TtsTextNormalizer` expands abbreviations case-insensitively (`AA`, `DEF`, `ATK`, `AoE`, `Jung`, `Lv`). A word such as "aa" in ordinary speech could be expanded. The normaliser tests do not cover this, and it was not verified against real phrases in this pass.

- **Recommendation:** add tests with ordinary words and decide between case-sensitive matching and a word-boundary list.

### OPEN-9 (Medium, content) — roam guide is out of date

`roam_guide.json` is at patch 2.2.16a with `meta.latest = true`; the live patch is 2.2.23. The other five guides are at 2.2.23. The validator warns about this. Refreshing it requires game-balance content (hero pools, objective timings, spell cooldowns). This pass did not change game content.

### OPEN-10 (Medium, data) — duplicated hero relationship fields

`heroes.json` carries two overlapping sets: `counters` / `counteredBy` / `synergies` and `goodAgainst` / `badAgainst` / `goodWith` (plus `bestPartners`). The model reads both, with fallbacks. Collapsing them needs a data migration.

### OPEN-11 (Low) — orphaned keys in data

Per the existing docs: `heroes.json.fixNotes` has a character-split first entry, and five `items.json.notes` keys are orphaned. `items.json.patchChanges` is not shown on the Patch screen. Not changed.

### OPEN-12 (Low) — `docs/refactoring-report.md` and `docs/ux-redesign.md` are historical

Both still describe the earlier pass ("no Gradle build run"). They are now dated records. A status addendum points to this review.

## 5. Decisions needed

**DEC-1 — ABI filters.** The release and debug APKs include native libraries for x86 and x86_64 (~90 MB). Restricting to `arm64-v8a` (and `armeabi-v7a` if needed) would roughly halve the native size. Trade-off: x86 emulators stop working for sideloaded APKs. The AAB is split by Play anyway. `overview.md` lists this as a planned item; I have not applied it.

**DEC-2 — `targetSdk` 36 → 37.** Lint flags it. Raising `targetSdk` changes runtime behaviour on Android 17 (edge-to-edge and other behaviour changes). Needs a device test first.

**DEC-3 — Robolectric on JDK 21.** The SDK-35 workaround keeps the test on JDK 17. Running it on JDK 21 with SDK 36 is also valid. If CI moves to JDK 21, restore `@Config(sdk = [36])`.

**DEC-4 — `extract.yml` trigger.** It is now manual only. If the automatic "push an archive" behaviour is wanted, the safety checks in the workflow still apply, but a root-level upload will still delete the repository's source tree. Keeping it manual is the recommendation.

**DEC-5 — Downloads survive focus loss.** `VoiceGuideManager.stop()` no longer cancels a voice-pack install (§3.4, item 15); only `cancelInstall()` does. This is a behaviour decision: a download continues when focus is lost. Confirm this is wanted.

**DEC-6 — Release signing.** Release builds without secrets are now unsigned. If a signed build is required for every run, add the secrets in GitHub; the workflow handles either case.
